# IR Workbench

A personal incident response case workbench. Local only, runs in Chrome/Edge by opening `index.html`.

## About me
- I'm a SOC analyst learning to build apps. I know Python; I'm new to HTML, CSS, and JavaScript.
- Explain changes in plain language, compare JavaScript to Python where it helps, and keep steps small.
- Before changing code, tell me the plan. After changing it, tell me how to test it (what to click, what to see in the F12 Console).
- Write all the code yourself (no "your turn" exercises). Explain the code instead, line by line where it's new.

## My IR principles (the containment / recovery features must reflect these)
- **Timing: contain everything at once, in one agreed window.** Partial containment tips off the attacker, who may react (e.g. set off ransomware early). I've experienced this first-hand, so it gets prominence.
- Talking to the client: state facts, don't assume. Say "not seen in the logs available", not "it didn't happen". A working hypothesis is fine if it's labelled as one.
- Containment actions may change the functional impact (isolating a server, disabling the VPN, segmenting can take services down): warn the client beforehand and revisit the impact assessment afterwards.
- Containment and recovery: assume the worst credible case, and record each assumption with its basis.
- Act on the logs you have; treat missing logs or telemetry as blind spots, not clean results.
- A foothold without enough endpoint / network telemetry means assume credential theft across the domain (privileged + service accounts, krbtgt twice, all users, Entra Connect as Tier 0, revoke cloud sessions / tokens).
- Before containment: preserve evidence, get stakeholder approval (approver, time, method), coordinate across teams (client IT, network, Thrive, EDR vendor, legal / breach coach, insurer), and use an out-of-band channel if email is compromised.
- My cloud storage and case folders are owned by Thrive (my employer, an MSP).

## Tech rules
- Plain HTML, CSS, and vanilla JavaScript. No frameworks, no build step, no npm.
- No external dependencies or network requests (no CDNs, no web fonts). The app must work fully offline.
- Must work when opened by double-clicking `index.html`, so no ES modules (`import`/`export`). Load files with ordered `<script>` tags and share state through one global object, `App`.
- Saving uses the File System Access API (Chrome/Edge). Personal view settings only (e.g. display time zone) are kept in `localStorage` (`App.loadSettings` / `App.saveSettings` in `core/state.js`); case data never goes there.
- Hashing uses Web Crypto (SHA-256).
- All timestamps are saved in UTC (`YYYY-MM-DDTHH:MM:SS`). There is ONE time zone setting: the sidebar's "Time zone (all tabs)" (`App.state.displayTimeZone`). Every time shown AND every time typed or pasted without a zone is in that zone (`App.time.toDisplay` / `App.time.fromDisplay` in `core/time.js`); forms have no zone pickers, only a label hint (`data-zone-hint`) and a "Saved as ... UTC" line. Pasted times that include a zone (Z, +08:00, epoch) are converted exactly. CSV exports stay in UTC.
- Colors are CSS variables in `:root` in `style.css`. Dark theme.
- Keep code commented for a beginner.

Rule: tabs never call each other directly. They read and write the shared case data in `App.state`, and redraw from it.

Highlight empty fields (Client and Summary and Reports tabs): a "Highlight empty fields (N empty)" switch (`App.emptyToggleHtml()`, one shared setting `App.state.highlightEmpty`, saved in localStorage) outlines every empty saving field in red (`App.markEmptyFields(panel)` in core/pickers.js; fields = `App.EMPTY_FIELD_SELECTOR`: data-field / data-rmm / data-person / data-critical / data-assumption; impact choice groups with nothing picked too). A tab that wants it puts the switch at its top and calls `App.markEmptyFields(panel)` at the end of render(); typing updates it live.

Reuse before rewriting: shared behavior lives on `App` in `core/` files. For any field that names a host/user/account, add `data-asset-picker` to the input (optionally `data-asset-picker="account,mailbox"` to limit asset types); `core/pickers.js` adds the case's assets as a pick list automatically, including for inputs drawn later.

Each tab has a label (button text in `index.html`, change any time) and a key (`data-tab`, panel `id`, `App.tabs.<key>`, file name). Keys will likely name the tab's data in `case.json`, so renaming a key after saving exists needs a migration.

## Data model
Everything is organized by case (one case = one ticket).

Cases live in a folder the user picks, OUTSIDE this project (never pushed to git; the app refuses a folder that looks like the project, and .gitignore blocks IR-Cases/ as a backup):
```
IR-Cases/
  INC-2041_acme-ransomware/
    case.json      all tab data: { format: "ir-workbench-case", schemaVersion: 4, savedAt, case: {...} }
    .history/      last 20 older copies of case.json (at most one per 5 minutes)
    evidence/      local evidence files copied in by the Evidence form (EV-001_name.ext), SHA-256 re-checked
    exports/       CSV exports (evidence, IOCs), time-stamped
  improvements.json   lessons collected across all cases
```

Saving rules:
- Autosave compares each case's JSON with what was last saved, so tabs never call "save": any change to App.state is picked up. Sample cases (`case.sample`) are never saved.
- Add new case fields in `App.caseDefaults()` (and client fields in `App.newClientInfo()`): `App.upgradeCase` uses them to fill in fields missing from older case.json files, and fixes ID counters. If a field is renamed or its meaning changes, raise `App.storage.SCHEMA_VERSION` and convert old data in `App.upgradeCase`.
- The cases folder handle is remembered in IndexedDB; after a browser restart the user clicks "Reconnect".

Case fields: ticket ID, title, client name, case types (one or more tags from `App.CASE_TYPES` in `core/state.js`, stored as keys like `"ransomware"`), priority (`App.CASE_PRIORITIES`: P1 / P2 / P3, P1 most urgent, stored as "p1"; schema 3 converted the old "severity" field: critical → P1, high → P2, medium and low → P3), status (`App.CASE_STATUSES`: Open, Contained, Closed), opened date, statusHistory (every status change `{ from, to, at }` in UTC, including the starting status; `App.statusChangedAt(c, status)`; the header shows "Contained <time>" / "Closed <time>").

Edit case: "Edit case" button in the case header opens a pop-up (`App.setupEditCaseForm` / `App.openEditCase` in core/sidebar.js, rules in `App.updateCaseDetails`) to change title, client, priority, status, opened date, and case types, with the status history listed. The ticket ID can't be changed (it names the case folder; the folder name is chosen once and remembered, so a new title doesn't rename it). Setting status to Closed while action items are open asks for confirmation, listing them. No automatic status hints (the user doesn't want them).

"Extract from raw logs" scans every evidence raw log (refanged first) for URLs, emails, IPv4, MD5/SHA-1/SHA-256, and domains (file extensions filtered out; no IPv6), merges repeats across evidence, takes first seen from the earliest timestamp on the same line (zone-less log times are read as the sidebar zone), and shows a review checklist: private IPs unticked, existing IOCs greyed out. Added IOCs are linked to every evidence item they were found in.
- Assets [assets]: only affected hosts and accounts (not every host seen). Entries with ID (automatic AS-001, ...), name, type (`App.ASSET_TYPES`, guessed from name: `@` or `\` = account), status (`App.ASSET_STATUSES`: suspected, confirmed, contained, remediated, clean), AD tier (own `tier`, "" = use the critical list's tier; `App.assetTier`), linked evidence IDs, notes. Tags after the name (`App.assetTagsHtml`, use it wherever assets are listed): [no EDR] [Tier 0] [BC-01], the BC tag when the name matches the Client tab's critical assets list (`App.criticalMatch`, compared with `App.normalizeHost`; nothing is copied, it's worked out on every redraw). Filter: All / Business critical only. A Tier 0 affected asset (`App.tier0Affected`) shows "⚠ Tier 0 asset affected" in the case header and suggests the "tier0-domain" assumption (assume full domain compromise). Added automatically when evidence is saved with "Add host / account to Assets as affected" ticked (unticked by default; same name, case-insensitive, links to the existing asset instead of duplicating), or by hand. Removing or unticking evidence removes the link but keeps the asset. The Host field in the Evidence and Storyline forms has a pick list of the case's assets; free typing still works. In the Evidence form, a host matching an existing asset auto-ticks the "affected" box.
- Post-incident [post]: what went well, what slowed me down, what to do differently. Feeds `improvements.json`.
